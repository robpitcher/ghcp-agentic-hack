# Module 2: Agentic Patterns — C++ / Hardware Skill Track Quiz

---

### 1. What should embedded C++ instructions encode?

- A) Durable rules such as fixed-width types, volatile review, validation gates, and hardware-safety boundaries
- B) Temporary chat preferences that change every session
- C) Secrets and board credentials
- D) A request to bypass repository policy

<!--answer: A-->
<!--explanation: Instructions are durable guidance for standards, boundaries, and expected behavior; sensitive content must not be stored.-->

---

### 2. Which content should never be placed in memory or a reusable C++ skill?

- A) A non-sensitive preferred build command
- B) A stable repository convention
- C) Secrets, regulated data, credentials, or proprietary customer identifiers
- D) A harmless formatting rule

<!--answer: C-->
<!--explanation: Memory and reusable skills must not persist sensitive, regulated, confidential, personal, or secret data.-->

---

### 3. Which strong prompt is best for reviewing a hardware-facing helper?

- A) Rewrite everything and make it faster
- B) Review this helper for fixed-width types, volatile correctness, masks, validation evidence, and stop conditions before edits
- C) Use any tool you want and merge the result
- D) Ignore build flags and focus only on style

<!--answer: B-->
<!--explanation: Strong prompts define task, scope, constraints, definition of done, and off-ramp before higher-risk edits.-->

---

### 4. What is the safest purpose for a repo-local embedded C++ skill?

- A) Package repeatable review guidance, scope, constraints, expected outputs, and acceptance gates
- B) Store private datasheets
- C) Replace human review of generated register code
- D) Grant every agent broad terminal permissions

<!--answer: A-->
<!--explanation: Skills package trusted recurring workflow guidance and should include acceptance gates and review boundaries.-->

---

### 5. Which custom-agent boundary is appropriate for firmware modernization?

- A) The agent may flash hardware whenever tests pass
- B) The agent may inspect files and propose plans, but hardware-impacting edits and commands require explicit approval
- C) The agent should hide tool output to reduce review burden
- D) The agent should modify compiler flags without asking

<!--answer: B-->
<!--explanation: Tool use creates auditable actions, so high-risk hardware, terminal, and build changes require constrained permissions and approval.-->

---

### 6. When is a background or cloud agent appropriate for C++ work?

- A) Any time a developer wants to avoid validation
- B) Long-running or parallelizable work with the right environment, permissions, and review path
- C) Updating register behavior from memory
- D) Tasks with no scope or definition of done

<!--answer: B-->
<!--explanation: Background or cloud execution is useful for genuinely long-running or parallelizable work, but it must remain observable and reviewable.-->
