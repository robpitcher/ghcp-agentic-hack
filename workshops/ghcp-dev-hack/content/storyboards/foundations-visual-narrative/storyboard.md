# Foundations Visual Narrative

## Current proposal

The viewer should understand that a human operator chooses what enters a harness request, observes conditional cached/fresh/output usage before routing again, and deliberately maintains active context by pruning stale evidence, archiving old history, and re-anchoring the current case.

The workshop owner accepted both revised text-only, clean-slate production stories on 2026-08-05. Existing character designs remain authoritative; all new poses and compositions are scene-specific. Acceptance authorizes only production preparation: it does not authorize keyframes, animation, paid calls, deck changes, publication, or release.

## Story beginning, transformation, and resolution

### Token — slide 14

- **Beginning, 0–4s:** Mergewell loads host/system instructions, repository instructions, selected context/tool results, and User request 1 into a harness station; fresh-input usage responds.
- **Transformation, 4–10s:** Response 1 exits and output responds; the harness conditionally retains an eligible unchanged prefix; Mergewell adds User request 2; cached and fresh lanes feed Turn 2 and Response 2 exits.
- **Resolution, 10–12s:** Mergewell compares result evidence with the three-band usage indicator and deliberately chooses the next model route.
- Exact current title preserved: `Model Routing: Match the Task`.
- Purrmission is absent; the collaborator is implied inside a sealed station.

### Context — sequence position (approved slide 22 after renumbering)

- **Beginning, 0–4s:** An active detective board shows what may compose context, reserved output headroom, and qualitative usage/focus cues.
- **Transformation, 4–8s:** Tangled stale/duplicate evidence obscures the current request before capacity is full; Purrmission flags the knot; Mergewell prunes and archives old history.
- **Resolution, 8–12s:** Mergewell re-anchors objective, essential evidence, constraints, and validation on a focused board.
- Exact title and relative placement preserved after `Context Recovery: Reset and Re-anchor`: `Context Lifecycle: Pack, Detect Drift, Recover`, approved slide 22.

## Shared visual and production language

- 1920×1080, 16:9, warm editorial direction from `content/modules/01-foundations/art-direction.md`.
- Brand-new compositions; no prior slide image, workbench, bag, chamber, deterministic scene, Sora candidate, extracted frame, or rejected composition may be reused.
- Agent Mergewell remains visibly human and accountable. Purrmission appears only in the context scene as a subtle focus guardian.
- Character/environment pixels remain text-free. All labels, caveats, gauges, decisions, and category names are native HTML/SVG overlays.
- Three locked-camera 4-second shots per scene, with exact first/final-frame continuity and one representative 4-second motion-study window.
- No GitHub mascot or character artwork, logos, fake UI, generated text, purple/faceless humanoids, mannequins, synthetic people, copied Inspector Gadget motifs, or hidden-state visualization.

## Cross-scene acceptance

- Both scenes run exactly 12 seconds and remain understandable as static reduced-motion posters.
- Every action that scopes, prunes, archives, validates, or routes is visibly performed by Mergewell.
- Cache is conditional and harness-managed; context composition/capacity varies by harness/product.
- Token visuals never claim exact boundaries, exposed proprietary prompts, guaranteed cache hits, fixed rates, user-controlled caching, electricity use, or automatic routing.
- Context visuals never claim hidden-state access, universal percentages/thresholds/commands, automatic compaction/recovery, erased history, or fullness-only failure.
- Complete object registers, native overlay scripts, safe areas, frame timelines, first/final compositions, motion notes, poster behavior, feasibility notes, motion-study candidates, and comprehension-based acceptance criteria are in the scene files.
